# Build Noodle Pads

You are starting a new repository for a web app called **Noodle Pads**. This prompt is the whole brief. Read it all before you write a file. Where it says *never* or *always*, that is a rule I have decided; where it is silent, make the call that fits the mission, name it in your report, and record it in the decisions file described in section 9. Section 10 lists the questions I want asked before you start, and the order to build in.

## 1. Mission and who it is for

The mission, word for word. Keep this text in the repo's contract file and steer every choice by it:

> Noodle Pads is a music studio anyone can pick up: kids, families, and grown-ups who love music but don't have the time for a pro studio. It starts as a soundboard: tap a pad, make a noise, annoy your family. Every next tool is one tap from what you are already playing with, so you learn by goofing around, never by lessons. Real depth (voices, beats, tunes, whole songs) is there when you reach for it. Goofing around counts as much as finishing a song.
>
> No ads. No required account. No social feed. No AI makes the music for you. What we measure is only to make the app better.

The north star is a music studio sized for kids and amateurs, in four parts: **make sounds** (Pads), **build patterns** (Beats), **arrange them** (Song), **play live** (Live). Rules for every feature on the way:

1. Each studio idea gets a kid-sized version, never a full clone.
2. Phones first: one thing per screen, big targets, nothing scrolls sideways across the page.
3. Anything can be undone, and nobody loses work by forgetting a step.
4. Depth hides behind levels (🧸 Kids, Regular, Advanced), and the next step sits beside what you are using.
5. No automation clips, plug-ins or audio recorded onto a timeline.

Who uses it: a five-year-old who cannot read, kids of ten to fifteen, and a grown-up who likes music production and has no time for a pro studio. Design for the five-year-old and the amateur at the same time: the simple path always sounds musical; the producer tools exist and stay out of the way.

Teaching happens by doing; there are no lessons. Things snap to the beat, defaults sound good, and labels say what happens ("Loops wait for the beat"), never the music word ("quantize", "velocity"). A kid learns bars by hearing the "1" land.

## 2. Promises and red lines

Never:

- Ads, a required account, a social feed, or AI that makes the music. No real names, emails or logins anywhere. Never promise "free" either: a paid version is not ruled out.
- A build step, a bundler, a framework or an npm dependency in the app. Plain HTML, CSS and ES modules, loaded as they are. Tools are stdlib Python or plain shell; the one exception is the headless-Chrome layout checker, which may be Node with no packages.
- Inline script or style, or any outside origin, in the Content-Security-Policy. Fonts are served from the site. The only outside host allowed is Cloudflare's Web Analytics beacon.
- A kid's name anywhere in the repo: code, tests, tools, file names, docs, commit messages. Write "a kid". Tests make names up (Pip, Juno, Toby, Wren). The repo is public; "Sandberg Family" is the most private detail allowed.
- Another product's name, brand or look in the app's words or its design, except a browser named where a feature only works there.
- The word "My" in a label: "🗂️ Beats", never "My beats", since each person only ever sees their own.
- A destructive action on one tap. The first tap turns the button red and asks ("Remove?"); the second does it; where a slip costs work, offer Undo too.
- A sound played by a scroll. On a touch screen a pad or key sounds when the finger lifts, if it stayed put (under about 10 px); a drag never sounds it. A mouse plays on press.
- A control under 44 px tall or wide, a line of controls that scrolls sideways across the page, or a name cut off (names wrap; long words hyphenate).
- Regex lookbehind in app code: Safari before 16.4 fails to parse the whole module.
- Silence when something is refused: a refused backup, item or delete gets a plain notice saying what and why.
- A rollback as the answer to a live problem: fix forward.

Always:

- Every control has a tooltip made from its accessible label, and a line in ❓ Help. Every icon-only control has an `aria-label`.
- Every notice fades by itself (8 to 10 s) and holds while a finger, the mouse or focus is on it. Notices float in one banner over the top of the screen, never in the page; the newest replaces the one showing; Undo rides in it.
- Empty places say what to do, in a centered dashed callout ("Tap squares, then ▶ Play. Or start from a 💃 groove.").
- Everything new a kid makes gets a whimsical made-up name up front ("Wobbly Thunder" for a beat); typing replaces it.
- Plain words a kid would use, short sentences, and emoji as the picture language. One emoji per kind, used everywhere that kind is named: 🔊 sounds, 🥁 beats, 🎼 songs, 🎬 takes, ⭐ voices, 👥 people, ✏️ sound edits, 🎛️ key sets, 🔗 shares, ⌨️ key layouts, 👆 touch layouts.
- Anything that comes in (a backup, an uploaded file, a cloud record, the kit file) is untrusted: checked field by field, capped, and anything malformed dropped with a notice.

## 3. Platform and shape

- One page, `web/index.html`, loading `web/app.js`, the only module that wires the screens together; no module imports it back. Each screen's pure rules live in a module with no DOM and no storage, so Node can test them.
- Storage is the browser's IndexedDB, one database. The device is always the working copy; the app never waits on the network.
- Hosting is one Cloudflare Worker on the free plan, serving the static files from `web/` and owning only `/api/…`, with one D1 database. Nothing else that could bill. The site is public at its own domain. Every push to `main` deploys through GitHub Actions; agents hold no deploy credentials.
- It installs as an app (a web manifest and icons; no install button) and opens offline after one visit: a service worker keeps the app first and the ready-made sounds after, a few at a time; online, every file still comes from the network first; `/api/` and `version.json` never come from the cache.
- A browser older than about Chrome 117, Firefox 115 or Safari 16.4 gets one plain notice ("This browser is too old for Noodle Pads…") from a tiny classic script that runs before the app, in place of a half-drawn page.
- Fonts: Anybody for titles and Atkinson Hyperlegible Next for everything else, both SIL OFL, served from `web/fonts/` with their licenses beside them.
- Screens: design at 375 px first, then make every screen work from 320 to 3440 px wide, and phones held sideways. Content fills to 2400 px, then centers; from 1400 px a screen's two natural parts sit side by side, except Beats, whose rows keep the full width.
- Colors: a pad palette of eight (red, orange, yellow, lime, teal, blue, pink, white) and eight person colors chosen to stay apart for deuteranopia, white text readable on all. A contrast test covers every text-on-color pair the app uses.
- The page behind the panels wears a faint random pattern each visit (a set of SVG tiles in the person's color, lightened); panels stay solid.

## 4. The screens

### 4.1 The frame

- Top: the title **Noodle Pads**; a round **person button** at the top right (their avatar on their color; it opens a list of everyone and 👥 People); ❓ Help and ⚙️ Settings beside it; 🧸 (open Kids now) from 600 px wide. Scrolled, a slim sticky bar keeps the person button, ❓, ⚙️ and ⬆️ at the left and the current screen's one key control at the right.
- Bottom: a toolbar with two **modes** and a stop: **🎉 Play** (🔊 Pads, 🎤 Live) and **🛠️ Make** (🥁 Beats, 🎼 Song), then **⏹️ Stop all** (⏹️ alone on a phone). The open mode is one light box showing its two screens, the one showing lit; the other mode is one button back to the screen it last had. Play stays left and Make in the middle, so neither moves under a finger. Space and Esc are Stop all too, except while typing, or when Esc has something to close or let go of first.
- Each screen's one-line how-to sits in the footer at the left; at the right, when the live build went up ("Updated Oct 19, 9:27 PM"; a tap opens About, with the release and the commit). No release number in the footer.
- One banner for every notice and Undo (section 2). A separate 🆕 "An update for Noodle Pads is ready." bar floats over the bottom when a newer version is live (checked on focus and every 10 minutes; it waits while anything records, plays or is open).
- Every dialog closes on Esc and traps focus. Sheets are bottom sheets under 600 px and centered dialogs above; a sheet's heading row, with its 44 px ✕, sticks while the sheet scrolls.
- Where a line of controls runs out of room it gives way in a fixed order: words drop before buttons, sliders become steppers, keys become pickers, and the least-used buttons fold into a ⋯ menu at the line's end. Buttons never shrink below 44 px to fit.

### 4.2 🔊 Pads

- Two sections: the person's own sounds, with a **New sound** pad first, then **Presets** in folding groups, each a bordered box with its emoji, name and count in the header: 🥁 Drums, 🧢 Hip hop, 🪘 Hand drums, 🎹 Notes, 🎶 Chords, 🎸 Bass, 🎮 Game, 💥 Effects, 🐵 Animals, 👽 Sci-fi, 🗣️ Voices, 🤪 Silly. Drums starts open; the device remembers which are open. About 145 presets (125 with Advanced off: the sharps, flats and extra chords are Advanced-only), under 6 MB together, each clip under 160 KB, mono 22050 Hz WAV.
- A tap plays the pad from the start; a hold (350 ms by default; a per-person setting of 350 to 1500) makes it loop, several can loop at once, and a tap on a looping pad stops it. A 🔁 Loop switch on the bar makes a plain tap start and stop a loop, for a hand that cannot hold still. While a beat plays, a loop waits for the next bar's "1" and repeats in whole beats or bars.
- A **pad size slider** at the top left of the pads' dark top band, from the smallest pads that fill a line (76 px) to one pad filling the line on a phone (400 px wide elsewhere). The setting is a share of that way, per person, so it means the same on every screen.
- **Pad skins**, per person, on every pad everywhere: Tiles, Slam buttons (an arcade dome whose ring fills as the sound plays), Lit pads, Switch, Spinner, Jelly, Googly eyes. Each is CSS under a root `data-skin`; reduced motion holds the moving ones still.
- **✏️ Edit sounds** (✅ Done) sticks at the top while scrolling. In it every pad shows a select circle at its top left and ✏️ and 🗑️ at its top right, floating with a bold ring so they read on any color, scaling with the pad. Tapping pads selects them; a bar offers 📁 Move to group, 🎨 Color · picture, 🪄 Voice (the sheet's voice chips, applied to all), 🔗 Share (one code), 🗑️ Delete (two taps, Undo), Select all (own sounds only) and Clear. 🗑️ on a preset hides it and 👁 brings it back; a group with everything hidden shows dimmed with "9 hidden". Pads drag to reorder within their section; a kid's own sounds can be in named groups of their own.
- **🎹 Who plays**: the Notes, Chords and Bass headers carry a picker ("💧 Pluck ▾") of instruments by family (Keys, Mallets, Strings, Wind): Notes has 11 (Pluck, Piano, Organ, Chip, Marimba, Steel drum, Kalimba, Guitar, Strings, Brass, Flute), Chords 5, Bass 3. It is a view over the kit, never more pads: each instrument's notes are presets of their own, keeping the note's fruit picture with a small instrument badge, played from one or two recordings per instrument resampled to each note, so extra notes cost no bytes. The pick is a per-person setting; anything already made keeps the exact preset it was given.
- The pictures teach: a note is always a fruit, a chord a weather, a bass note an animal, on every instrument. Every other preset has a picture that shows its sound.

### 4.3 The sound sheet (New sound, or a pad's ✏️)

- The sound's name is the title (tap to rename, 24 characters). ▶︎/■ at its left plays the sound as it sounds now (Space too). Under the title: the wave, lighting up as it plays, with 👂 **Plain** (the sound with no voice, at its pad's loudness) and, with Advanced, ✂️ **Trim and edit** and 🧩 **Chop into pads**. On a kid's own sound, 🔊 **Even it out** matches how loud it seems to the presets: BS.1770-style loudness, one gain edit with Undo.
- New sounds come from the microphone (hold or tap to record, a meter, a 10 s cap; the mic taken raw, with no echo cancelling, noise suppression or auto-gain), from a file (under 10 MB and 120 s), or from ✨ **Make one** (a small synth recipe: Laser, Boom, Tss, Clap, Siren, Coin, Wind, 🎲). Every sound is scaled so its loudest moment matches every other sound's.
- **Voices**: Loud, Chipmunk, Fast, Slow, Monster, Robot, Stadium, Walkie-talkie, Underwater, Alien, Clones, Stutter, Backwards, as emoji-only chips. **A voice is knob settings**: tapping a chip slides the knobs in **Layers** to where that voice puts them, and a line under the chips says what it did ("Chipmunk is: higher +9, faster 1.74×"); a second chip adds on top, the last tap winning a shared knob; 🎲 Surprise me stacks one to three; moving a knob makes it your own. A few voices keep a ✦ special part no knob makes.
- **Layers** is one row per layer, top to bottom in play order, like a beat's rows: emoji, name, keys or a slider, 🔈 mute, ✕. Always there: Deeper ↔ higher, Slower ↔ faster, Warble, Softer ↔ louder, Echo. **+ Add a layer** adds ⏪ Backwards, Muffled ↔ Bright, Robot, Crunch, Stutter and, with Advanced, the kid's own steps (echo, room, fade…), which drag into order. Slow and Fast keep pitch. An ⚙️ Advanced switch sits at the bottom of Layers.
- ⭐ **Save voice** keeps the knobs as the kid's own voice (a name and emoji, never pre-filled with a kid's name) that travels with the person; ↩️ **Reset voice** puts every knob back. With Advanced: 🎵 Find its note (stores the sound's root, so tune rows play it in tune) and ➕ Mix with another sound.
- Voices never change the recording. The original is kept; voice, knobs, trim, part edits (Backwards, Silence it, Louder, Quieter, Keep only this) and fades are settings, rendered from the original on load and cached. A sound saved with an older voice plays exactly as before.
- Closing the sheet with unsaved work asks, in a small centered modal: Keep editing or Throw away. Beats, songs and layouts save as you go and never ask.

### 4.4 🥁 Beats

- Each person has one **open beat**, which saves itself on every change. With nothing else open it is their **scratch beat**: never listed, saved once it changes. The beat bar: 🥁 name (tap to rename) · ✏️ or 💾 **Keep** (turns a scratch into a named beat in 🗂️ Beats; after a groove, "Admiral Avocado (House version)") · 💃 **Grooves** · ⌨️ **Keys** · 🆕 **New** (stops, keeps a scratch with hits first, opens a blank one) · 🗂️ **Beats** (open, 📌 pin, ⧉ duplicate, 📄 save as a `.beat.json` file, 🔊 As a sound, ⬇️ Audio file, 🗑️ delete; 📥 Load a beat file). On a phone the three middle tools take a worded row above the title.
- Under the bar, 8 **pattern chips**: pinned beats first, then the most recently used, oldest made first, so a tap never moves a chip; a tap while playing switches at the next bar line without a gap.
- The **control bar**: ▶ Play; ● Record (with Keys on); the tempo (a slider pulling toward common tempos, every 10 from 60 to 180, and 128; tap the number to type; on a phone the tempo is one key, "100 ▾", opening a 🐢 slider 🐇 row under the bar, the same on every screen that has a tempo); ⏲️ Click track; bars (1 · 2 · 4); the time signature (Advanced: 4/4, 3/4, 5/4, 6/8, 7/8; a pill is always a sixteenth and BPM always counts quarter notes); Swing as three keys (Straight · Swing · Shuffle, which play the off-beat eighths late); 🎚️ Mixer; ⇆ Move; ✏️ Layout (with Keys). On a phone it is a grid of 48 px keys in columns. Scrolled, it tucks into the slim bar as ▶ and a ▾ that drops the whole bar down.
- **Rows**: up to 16, each one line: a head stuck at the left (⠿ grip · emoji · name · 🔊 speaker; emoji · 🔊 on a phone), then its pills, 32 × 44 px with round ends, under a ruler of bar numbers, every row scrolling sideways together inside one box; a phone shows about half a bar. The first pill of every bar is brighter with a white dot, and the first of each beat a shade brighter. While playing, the box follows the playhead a screen at a time until the kid scrolls. The row's emoji opens its menu: 🔄 Change sound, 🔔 Let it ring (hits overlap instead of restarting), 🧹 Clear, ✕ Remove (each asks first, with Undo; an empty row goes on the first tap), ↑ ↓ Move. The speaker: a tap mutes, a hold or drag sets the row's loudness.
- **Pills**: one tap on or off, never two; a hold makes a loud hit (a white ring, about 3.5 dB up); pills sound only while the beat plays. With a mouse, lit pills pick and drag like objects (click, Ctrl/Cmd, Shift, a box, Delete, double-click, Undo); with a finger, ⇆ locks the pills so a tap picks and a drag slides, with All · None · Invert.
- **+ Add a row** opens the sound chooser (the kit once, by group, then each person's own sounds; a tap previews and ticks; Add puts in a row per tick, the next unused sound pre-ticked). **🎹 Add a tune** asks "Who plays it?" and makes a **tune row** that stores notes (pitch, start, length) and opens 🎹 **the piano roll**: its own screen, note names up the side, bars across, a tap adds a note a pill long, a sideways drag stretches it, a tap takes it out, scale lock on (♯ All notes for twelve), two octaves at a time, the other rows as a strip on top, ▶ Play with a playhead, ½ Half pills with Advanced, ✅ Done. Squares are at least 32 px.
- **💃 Grooves**: about 50 ready-made beats in seven style groups (💃 Dance · 🎤 Hip hop · 🎸 Rock, pop & country · 🙌 Soul & gospel · 🌴 Latin & Caribbean · 🌍 Drums of the world · 🎷 Swing & odd times), many with bass and chords, each card with a line on what to listen for and a ▶ sample (one pass, at most 4 s). A groove loads into the scratch beat, or ➕ adds its hits to the open beat, with Undo; the beat keeps playing. At the top of Grooves, a 🎧 **From a song** card: listen to another tab, the microphone or a file and turn what it hears into beats (kick, snare and hat rows with the app's closest sounds; tempo, time signature, swing; a part ends where the pattern or tempo changes, and two or more parts also make a song with tempo marks). The song itself is never saved.
- **🎚️ Mixer**: a column per row (a fader, Mute, Solo, one effect: Room, Hall, Echo on the beat, Muffled, Bright, Crunch, Warble, Robot, Louder) and a Master column; it saves with the beat; on a phone the columns scroll sideways under a pinned Master.
- **⌨️ Keys** (remembered per device) shows the keys of section 4.6 under the open beat, with ● Record: a count-in (a big colored number per beat on a disc over the keys, then a red GO!), then the beat goes round and every key hit snaps forgivingly onto its pills, pass after pass, until Stop. A beat played into its last bar on the first pass grows 1 → 2 → 4 bars. Playing a sound with no row makes its row at once, rows in keyboard order; a full beat reuses an empty row. The playhead follows what is heard, with the speaker's delay taken off; the tempo can change while recording. ↩️ Undo puts the beat back. Tap ⏲️ three times in time to set the tempo.

### 4.5 🎼 Song

- A **playlist**: a song tempo (60 to 180; the first beat put in sets it), 4 lanes to start, up to 8 (➕ Add a lane), each with a name, a picture and a speaker. Time runs across in bars at the song's tempo, bar numbers on top, the lanes scrolling sideways inside their box and following the playhead; a phone shows four lanes and scrolls the rest down.
- A strip of the person's beats above the lanes (the scratch first, once it has a hit): **pick a beat, then tap a spot** on a lane for a block, played once, never overlapping another on its lane. Tap a block to select it: drag its ⟷ end or ➖ ➕ to repeat it; ✏️ opens its beat in 🥁 Beats with a ↩ Back to song chip (when the song plays that beat more than once it asks: Edit it, or Edit a copy); 🗑️ takes it off (asks first). ↩️ Undo covers blocks, lanes and tempo.
- **Tempo marks** ("from bar 17, 120 BPM") show as BPM chips over the ruler for everyone and are edited with Advanced; every lane follows them, so bar lines stay lined up.
- ▶ **Play song** plays every lane together from bar 1 or from a tapped bar, with a playhead; blocks playing light up; one thing plays at a time (the song stops the beat and the beat stops the song). 🔊 **As a sound** renders the mix, up to 3 minutes, to a new pad; ⬇️ **Audio file** renders it as a WAV, to the share sheet on a phone and a download elsewhere. A block whose beat was deleted stays greyed as "Deleted beat" and is skipped. Songs are a list like beats: a scratch song, 💾 Keep, 🆕 New, 🗂️ Songs.

### 4.6 🎤 Live

- **The keys**: 40 sound keys laid out like a keyboard's number row and three letter rows, drawn like a periodic table (big letter, emoji, name, colored by family, with a legend), alternating like bricks on wide screens, played by the real keys (matched by the letter typed, so a keyboard remapped in its firmware lines up) or by tapping (the finger-lift rule; held still, a key loops). A pressed key lights, a looping one pulses, a hit ripples its color across nearby keys, and a playing beat flashes its keys in time; calm under reduced motion; no key lights more than three times a second, whatever hits it. By default the number row is a scale (C to high C, then Ding and Ta-da) and the kid's own sounds sit on Q to P.
- **👆 Pads**: on a phone always, and a choice from 700 px: bands of big touch pads, one group each, sized S/M/L, the same layout on Live and on Beats with Keys. A layout can also be a **grid** of blocks side by side (ready-made grids: Two and one, Four corners, Three across, Side by side), each block one group, its pads as big as the block allows; an edge between blocks drags like a window splitter, in twelfths; a block's ⋯ splits or joins it (at most 8 blocks, 4 in a line, 3 splits deep).
- **✏️ Layout**: a focused full-screen editor with ⌨️ Keys | 👆 Pads in its title. Keys view: Layouts on top (the kid's own ⭐ first, then ready-made ones: four by kind of playing and one per instrument family), the 40 keys in the middle, Sounds by group below; tap sounds then a key, or drag (a sound onto a key, a group onto a row, a key onto a key swaps, a key off the board clears); sounds in the way move to free keys. Pads view: ⭐ Layout, saved ones, four ready-made band layouts, the grids, then the bands with ⠿ and S M L, a tap on a pad to swap it, + more, + Add a group (at most 8). Named saves, rename, delete (two taps) and ↩️ Undo throughout.
- **The control bar** matches Beats': ● Record, the click's tempo (100 BPM for the visit) and ⏲️ Click track (tap tempo on it), then 🔔 Let it ring, ✏️ Layout and 🎬 Takes, folding into a ⋯ only where they do not fit.
- ● **Record** keeps everything played as a **take**: a replayable performance on the audio clock, with the beat's hits if one was playing. The **take card** after a take: ▶ Play (■ while playing), 🔊 Make a sound (a second time asks "Make another?"), 🥁 Make a beat (hits snapped to sixteenths at the click's tempo or the best fit, a row per sound, opened on Beats with Undo), ✏️ Rename, ↩️ Undo. 🎬 Takes lists them.

### 4.7 🧸 Kids (the Kids level)

Four picture screens in place of the regular app, for a five-year-old: no words to read, nothing to delete, edit, share or set. A grown-up leaves by ⚙️ and a **sum** (a number from 12 to 39 plus one from 6 to 9, on big number keys; three wrong in a row waits 30 s). Held sideways on a phone, the tabs stand in a column at the left so nothing is cut off.

- **🔊 Pads**: big picture pads in swipeable pages (a 👆 hand pulses on the first pad until it is tapped): the kid's own sounds first, then only presets whose picture shows the sound they make (animals, silly, effects, game, sci-fi, spoken callouts, the drums that look like what they are); never a note, chord or bass note, and no picture used twice on a screen. Startling sounds (explosion, siren, alarm, airhorn, evil laugh, buzzer) wait on the last page. A round skin button at the top left moves to the next skin, Kids' own. A slider or a pinch sets the size, Kids' own.
- **🎙️ Record**: a big mic. A tap counts 3, 2, 1 on its face, then it listens until the next tap; a hold listens at once and the lift stops it; 10 s at most; the mic swells and glows with the voice. Three voice buttons, 🤖 🐭 👻, change the last recording at once. It becomes a pad.
- **🥁 Beats**: four drums (🦶 kick, 🪘 snare, 🪇 shaker, 👏 clap) of eight squares, ▶️/⏸️, 🐢 80 and 🏃 140 BPM (neither lit: 110). A new beat starts with a simple kick and snare lit, so the first ▶️ is never silence. It is Kids' own hidden beat per person, never the grown-up's; a beat made on 🥁 Beats sounds the same here (its tune in tune, its loud hits, its swing).
- **🎹 Keys**: eight colored keys, pentatonic always (C D E G A, high C D E; the high ones the same fruit, smaller, with ✦), playing while held, several fingers at once, lying like a xylophone on a phone. A round instrument button (Pluck, Piano, Marimba, Steel drum, Kalimba; every key wears its picture) and ● record: 3, 2, 1 at the beat's tempo, then the beat goes round once while the keys land as a tune row; the tune is kept in 🗂️ Beats with 🧸 in front of a fun name, so a grown-up finds it; only the newest 20 stay.
- Spoken prompts ("Tap a picture!", "Tap the mic and talk!", "Tap the squares!", "Tap the keys!") play once per kid per screen, only when a family member's recording exists, never over sound.
- ⏹️ stops everything; Esc stops at once. 🧸 in the regular app shows Kids now for anyone, for the visit.

### 4.8 People, the welcome, PINs

- **Nobody types a person's name.** A generator makes alliterative fun names ("Friendly Sloth", "Captain Cranberries"); 🎲 deals a dozen to pick from; the picture is one emoji from a short list or from the full searchable list (…); eight person colors. A new device starts with one person with a fun name and a random picture, never "Me". Every person id is random (`p-…`).
- **👥 People** (from the corner button, never from Settings): one line per person (picture, name, counts, ☁️ and 🔒 state); ➕ Add a person; ☁️ Open from the cloud. A tap opens the **profile sheet**: 🎲 Pick a name, the picture, the colors, ☁️ In the cloud (a switch), 🔒 PIN, and 🗑️ Delete in a red-edged box of its own (two taps; a double tap only asks; for someone in the cloud a separate button then asks to delete the cloud copy, with ☁️ Keep taking its place). The count line ("🔊 27 · 🥁 4 · 🎼 1 · 🎬 1 See all ›") opens **🗂️ See all**: everything of theirs by kind, each row playing in place, with ⬇️ Export a backup of just them.
- **The welcome** for a device's first person and everyone added later: **👋 Who's playing?** (three picture cards drawn as pads: 🧸 Little noodler · 🎵 Tap and make beats · 🎛️ Show me everything; no ages; a tap plays a sound and sets the level; Skip keeps Regular; the first person also gets ☁️ Open from the cloud), then **Pick your stage name** (a big face, six fun names and 🎲, pictures, colors, Skip, ▶ Let's play; Kids picks only a picture and a color). Nothing blocks the first sound.
- **One-time tips** in the banner, once per person, the first time a thing matters (three pad taps: "👆 Hold a pad to make it loop."; the first visit to Beats, to Song, to Live; the first sound sheet); **hint dots** on ⌨️ Keys, 💃 Grooves and 🎚️ Mixer until first tapped; and a **level-up nudge** ("🎛️ Want more knobs?") for a Regular person who reaches for Advanced things three times over two visits. What has been seen is a per-person setting, synced. ❓ Help has 💡 Show tips again. Kids gets no words: the hand, and a mic wiggle.
- **👋 Who's playing now?**: when the person on show is deleted, or at start when everyone has a PIN, a pad per person to pick from; only a pick closes it.
- Nothing of a PIN person is read or changed past their PIN, asked once per visit: their profile, See all, Export, Delete, their sounds in choosers, and backups.

### 4.9 ⚙️ Settings and ❓ Help

- ⚙️ Settings, folding sections closed at first (the device remembers), a chip on each saying its state: 🔗 Sharing (🔗 Shared with me: open a code; ▶ Play, 🎛️ Remix, ✕ Remove); 💾 Backups (💾 Save a backup, 📂 Load a backup, with a line saying what a backup holds by kind and size); 🎚️ Level (🧸 Kids · Regular · Advanced, per person); 🎨 Look (the seven pad skins as sample pads; Hold to loop: 0.35 Quick, 0.5, 0.75, 1, 1.5 Slow); 📊 Data sharing (📊 Share play data and 📮 Send problem reports, both on by default, with nothing about what is collected); and About, always open: one line on what the app is ("Tap a pad, hold it to loop, record your own sounds and make beats. Made by the Sandberg Family."), the version with the commit linked, then Privacy policy · Send feedback (behind the grown-up sum; a centered dialog; up to 2000 characters; nothing of the sender) · Show the welcome again.
- Level changes what shows. Regular is the default. Advanced adds each row's speed, time signatures, tempo-mark editing, the sharps and flats, ✂️ Trim and edit, 🧩 Chop, 🎵 Find its note, ➕ Mix, the kid's own steps and ½ pills. Kids is section 4.7. Settings travel with the person (level, pad size, skin, instruments, hold to loop, what they have seen); the keyboard choice, the report switches and the device code stay with the device.
- ❓ Help: a picture reference, one tab per screen (Pads, Sounds, Live, Beats, Song, Settings), opening on the current screen's tab; each line draws the control with its real label and one sentence; Advanced tools marked. A test fails when Help names a label the app no longer has, or misses a key control.

## 5. Sound engine rules

- One AudioContext for everything; its output goes master → limiter → soft clip → analyser → speakers, so stacked sounds never clip. On iOS ask for playback audio, so pads sound with the ringer switch off.
- One beat **scheduler** on the audio clock (a 25 ms tick with one lookahead) plays every beat: Beats' loop, Kids' beat, Song's planned list and a groove's sample, with hooks for what each leaves out. No screen has a timer of its own. A new run stops the one playing, through its owner. The click track is its own small schedule.
- One **mix graph per beat** (each row's level per hit, mute and solo by not booking hits, one effect per row, a master) for live play and for every offline render alike.
- A sound's chain (edits, trim, fade, voices, knobs, steps) is rendered offline from the original and cached per settings; live sliders drive nodes while the sound loops and render on release. Slow and Fast keep pitch, in a stretch worker off the page. After every voice the quiet at both ends is trimmed (below about −42 dB, keeping 30 ms before and a 150 ms fading tail).
- Loudness: every sound plays with the same loudest moment; every preset then carries a `level` (dB, at most 0), so all play as loud as the middle one on a phone, worked out by a tool whose test fails until the kit file has them. A level never turns a sound up: a quiet preset is remade. Kicks, booms and bass notes carry overtones above 180 Hz, so a phone speaker plays them.
- Pads, keys and touch pads all reach a sound through one tap path; Kids calls the player itself. A row's next hit cuts the previous one with an 8 ms fade unless 🔔 Let it ring, which allows up to 8 overlapping. Tune rows play a sampler: the sound resampled to each note, fading at its end, notes overlapping.
- One microphone recorder (raw, 10 s cap, a meter, the count-in's numbers) shared by the sheet and Kids. One WAV encoder (16-bit) for every render that leaves the app.
- Presets that exist in the world (drums, animals, a siren, an alarm) are real recordings under CC0 or CC BY, credited in a license file; game, sci-fi and cartoon sounds are synthesized by a stdlib Python tool with a small recipe each. No film clips, no product sounds.

## 6. Data

- **The kit** (`web/boards.json`): `kitGroups` (id, name, emoji) and `kit`, each preset `{id, label, emoji, color, file, group, level?, advanced?, inst?, plays?, shift?, chord?}`; a palette; no people. Every person gets their own copy of every preset, with the id `<person>-<kitId>`, so renames, hides and order are per person and a beat's rows can name kit sounds by kit id.
- **IndexedDB stores** (one database, versioned upgrades, every stored shape kept loading forever): `clips` (a sound: its audio and its settings), `overrides` (a person's edits to kit copies), `orders` (pad order and own groups, per person), `patterns` (the open beat, per person), `beats` (every beat, scratch included), `people`, `settings` (the device's), `prefs` (per-person settings), `decks` (the live keys and touch layout, per person), `takes`, `layouts` and `touchLayouts` (named saves), `songs` (the open song) and `songbook` (every song), `voices` (a kid's own), `cloud` (this device's link to each profile) and `bases` (each record as last synced). Settings are declared in one registry with a default, allowed values and a scope (person or device); anything remembered in localStorage is listed in a start-up test that sets them all.
- **Record shapes**, roughly. A sound: `{id, personId, label, emoji, color, type, bytes, voice?, amount?, fx?: [{type: 'voice', voice, amount}], tweaks?: {pitch, speed, echo, volume, warble, …}, trim?: {start, end}, edits?: [{kind, start, end, amount?}], fade?: {in, out}, root?, synth?, from?: {id, how}, exact?, group?}`, storing only what differs from normal. A beat: `{id, personId, name, bpm, bars, signature, swing, rows: [{clipId, steps, accents, volume?, muted?, rate?, ring?, melody?, tune?: [{p, s, l}], fx?, solo?}], volume?, fx?, pinned?, kidsTune?}`. A song: `{id, personId, name, tempo, tempos?: [{bar, bpm}], lanes: [{name, emoji, muted, volume, blocks: [{beatId, bar, times}]}]}`. A take: its events `{t, clipId, kind, ring}` on the audio clock, and the click's `bpm` when it was on.
- **Backups**: one zip, `backup.json` plus `sounds/<id>.<ext>` for each own sound, and from format 1.2 each own sound again **as heard** (`sounds/<id>.heard.wav`, rendered with its voice and edits, for a future native app to import with no voice engine). `app: 'noodlepads'`, `format: '1.x'`; every 1.x loads in every later copy, and golden backups of each format are kept in the tests forever. **Loading merges by id**: the same record is skipped; a different one under a used id is kept under a new id, with every reference following; nothing here is replaced or deleted; loading twice changes nothing; the notice says what came. A one-person backup asks: ♻️ Restore them, or load it all into someone here. Limits: 300 MB unpacked, 5000 files, 8 MB of JSON, 80 MB a sound. The format is written out field by field in a doc a test keeps true.
- Ids: a person is `p-` plus random letters; a beat, song, take or sound is a random id; the scratch beat and song have reserved ids per person (`beat-scratch-<person>`, `song-scratch-<person>`); Kids' hidden beat is `beat-kidsown-<person>`.

## 7. The cloud

- **Nobody goes to the cloud by themselves.** A grown-up turns ☁️ In the cloud on in a person's profile: the grown-up sum, then a 4-digit PIN typed twice, with one line in a chalk box on what becomes public. The Worker makes, lists and opens only profiles with a PIN. Off (or Remove PIN: the same thing, the same words) brings their latest here, then deletes the cloud copy and every share code; if the latest cannot be brought, nothing is deleted.
- **Public by design, said plainly**: anyone can see the list of the 300 most recently used profiles (fun name, avatar, color, whether it has a PIN, when its look last changed), play a sound whose unguessable link they have, and play a share whose code they have. The PIN is not security. The disclosure in the app, README and the privacy policy must stay true, and a test ties each claim to the code.
- **PIN**: PBKDF2-SHA-256 with a per-profile salt. Obvious PINs (1234, 0000, four of a digit, a straight run, a short list) are refused on the pad and by the Worker. It is asked on each open on every device unless 🔑 Remember on this device (offered after the PIN; Forget this device is behind the sum; 🔑 Forget all N devices cuts every device off). 5 wrong tries wait 10 minutes, and every further full window doubles the wait, up to a day, said on the pad with when it opens again. A PIN changed elsewhere locks the person here until typed; 🤷 I don't know the PIN (two taps) deletes them from this device. A forgotten PIN is reset by a tool that picks a random PIN and shows it once.
- **Sync**: the device is the working copy. A person in the cloud syncs on open, 20 s after the last change, on every focus and blur, and every 5 minutes while shown and focused; never on a timer while hidden. A sync is a pull, a **three-way merge** of each record against its last-synced copy (unchanged on one side takes the other; changed on both merges field by field, a beat pill by pill, the newer edit winning a clash; no safe merge keeps both; a delete against an edit keeps the edit), then a push that names the rev it pulled, which the Worker refuses to overwrite past. Audio uploads in pieces of at most 1.9 MB, since a D1 row holds 2 MB. ☁️ Open from the cloud shows a locked sheet: a spinner, then a bar filling by bytes ("🔊 5 of 12"), then ✓ with Play as them; 20 s with nothing arriving offers 🔄 Try again or ✕ Don't bring them.
- **Share codes** (`ABCD-2345`, with no 0/O or 1/I) are a read-only snapshot of one sound, beat or song with a rendered preview, for anyone with the code until 🚫 Unshare; 🎛️ Remix puts an editable copy on your board that outlives an unshare. Every code asks the PIN, even on a remembered device.
- **Free-plan guards in the Worker**: 25 MB a sound; 40 MB of sound and 10 MB of records a profile; 400 MB and 60 MB site-wide; a push at most 4 MB and 200 records; a day allows 50 new profiles site-wide and 3 per network address (counted under a daily keyed hash of the address, never the address itself), 5,000 pushes and 500 shares, and one profile 1,000 pushes, 2,000 sounds and 50 shares; opening a profile 10 a minute per profile and 60 per address, checked before the PIN; an edge rate limit of 300 requests per 10 s per address. A profile never used within a day is deleted when the next is made. Over a cap, the app says so in a kid's sentence ("This network has put as many people in the cloud as it can today") and keeps working on the device.
- **What else leaves the device**: 📮 problem reports (the event log cleaned by a rule table, so no audio and no names ever go and every free-text field is redacted; a device left at the default sends only after an error or a tap that made no sound; kept 14 days); 📊 usage events (one `track()` call checked against a list of allowed events, batched to the Worker, every device with its own random code; the switch stops everything, player metrics included); **player metrics** for cloud profiles only (device family, browser, OS, width bucket, and the country of each open, pull, push and share; never an IP, a city or a user-agent string; 14 days, a device's row 90); and feedback (typed on purpose, behind the sum, kept 90 days). An IP is used only in the moment, to limit abuse, and never written anywhere.
- A schema change is a new migration file plus the full schema, checked equal by a test; the deploy applies migrations before the upload, so keep them additive. Agents never write to the live database; the deploy's live checks make and delete throwaway profiles of their own, proven by a secret.

## 8. Quality bar: what done means

- **Tests** run with `node --test` and no install: a stand-in DOM builds the page from `index.html`, so the real app starts in a test; a stand-in IndexedDB and a stand-in D1 (on Node's SQLite) cover storage and the Worker. Every change ships with a test that fails without it, and a `prove` recipe runs the test against the committed copy to show it. Whole-repo guards: the contrast suite over every text-on-color pair; every `web/` file named in the service worker's shell list; no regex lookbehind; every localStorage key in the start-up test; every Help label existing in the app; every settings key declared; the privacy claims matched to the code; the backup-format doc naming every store and field; the architecture doc's claims checked against the code; every logged field having a cleaning rule; every preset at its level; the migrations equal to the schema; a syntax check of every module and tool first. A test file ends by itself, or fails naming what holds it. Judge a run by its exit code only.
- **Looks** are checked in a headless Chrome by one Node tool, `look`: at 320, 375, 700, 900 and 1100 px (and 1366, 1920, 2560 and 3440 with `--wide`; phones held sideways with `--landscape`; 680 px tall for a phone with its browser bar showing) it reports sideways scroll, console errors, CSP blocks, controls under 44 px and controls overlapping in a fixed bar, saves a full-page screenshot of each, and exits 1 on any failure. Named views open each sheet and mode; `--skin all` and `--bg` fix the random parts; `--cpu 4` finds timing problems a fast machine hides; `--reduced-motion` shows what a device asking for less motion sees. A `taps` check taps Pads, Live and Kids with a synthetic finger, fresh, after a mode switch, and after a freeze and thaw; each must sound.
- **Live checks** after every deploy: an API round trip and two headless devices syncing on the live site, each with a throwaway profile deleted in a `finally`; and a daily read-only check that the site answers.
- What cannot be checked here (sound by ear, real touch, a real old browser) is listed in the state doc as "not yet tried by a person", never assigned to a person as a task.

## 9. How to work, and what the repo must carry

- The repo is the memory. A session may start with only the repo, so everything the next session needs is in a file: a **contract** file (how to start, test, run, ship, and the rules); a **decisions** file (every rule I decide, one row: Rule · Why · Since, under 40 words, by topic; it outranks every other doc; a replaced rule is deleted, never annotated); a **state** file (what is live and in flight, in the present tense, replaced and never appended); an **ADR** folder (why each big decision was made: what forced it, what was picked, what was turned down, what it costs; rewritten in place when a decision changes); a **questions** file (open cards for me); a **TODO** file (one list: what I do and what agents do, in order; a line is deleted when done, never ticked); a **guide** (every screen, and how things are stored); a **file map** (one line per file); and an **architecture** folder (how the code is wired, one file per area, with "one or several?" answers and "to change X, touch …").
- Each module opens with a comment saying what it owns. Comments say what the code is for and why, in plain sentences.
- Commits: `<type>: <summary>` (feat, fix, style, refactor, docs, chore, test), with a bullet body at the level a user notices. A change to `web/` bumps a release number `1.0.<commit count>` in the same commit; CI refuses one without it. Every push to `main` deploys; read the run after a push, and fix a red one first.
- Recipes in a `justfile`: `setup` (git hooks), `doctor`, `test`, `serve`, `look`, `taps`, `prove`, `version`, `ship`, `land`, `ci-wait`, the cloud chores (`cloud-profiles`, `cloud-sql`, `cloud-migrate`, `cloud-prune`, `cloud-reset-pin`, `cloud-backup`), `logs`, `placeholders`, `emoji`, `preset-loudness`, `policy`. Every recipe has a doc line and a README row; a test checks. Improve the tooling in every session: a step that was slow, repeated or easy to get wrong becomes a recipe, in its own commit.
- **Ask me the right way.** Before a long build I will not watch, ask every decision up front, in one batch. While I am in the chat, ask each question as it comes up, one at a time, and act on the answer. For a real judgement call (a layout, a name, what a control does), name the options, recommend one, and ask. **Mockups first** for a new screen, a new layout or a moved control: show screenshots from `look` of a draft, or an HTML widget, and get my OK before building; fixes and restyles inside an agreed design go straight ahead. Medium- or high-confidence work goes ahead without asking; only low confidence, a clash with the decisions file, or a new screen or control waits for me. Record every request the moment it arrives, in TODO or the state file. Make the smaller calls yourself and name them in your report; do not log them anywhere.
- **Review every change through a council** of named lenses before it lands: mission keeper, children's privacy and safety, child psychologist, pre-reader specialist, accessibility, kids' mobile UX, time-poor amateur, skeptical parent, music educator, working producer, sound designer, audio engineer, performance, browser and offline compatibility, security, storage and sync, reliability, test and QA, web-platform architect, Android (a future native port), developer experience, docs. Scale the round to the change: all seats on a new screen, at the mockup stage; the data seats on a stored format or the cloud; one or two on a fix. Brief each seat blind with the change only, run a round in parallel, require evidence with every finding and a biggest risk even on a pass, and let a seat block a feature or a deploy when it can name the mission line or red line it breaks. Results go into the work (code, tests, docs, decisions, ADRs) and one `Council:` trailer per commit; never a separate log. A block against one of my rules comes to me.
- Reports to me: lead with the answer or the next action, number multi-step work, give estimates in minutes, keep lists to five items, say "likely cause" until a cause is proven, and end with the one next step I can take. Verify before you assert. Call agents agents, never people.
- Writing in the app and the docs: short sentences, plain words, say what a kid would notice and then the reason; never "not X but Y" framing.

## 10. Build order, and what to ask me first

Build in milestones, each shipped, looked at and reviewed before the next. Do not build everything at once.

1. **The soundboard** first: the frame, Pads with the kit, the sound sheet with recording, voices as knob settings, Layers and Save voice, Edit sounds, people with fun names, the levels Regular and Advanced, Settings, Help, backups with merge, the service worker and install, the tests and `look`. Stop here and show me every width.
2. **Beats**: the open beat and the scratch, rows and pills, the scheduler, Grooves, the Mixer, tune rows and the piano roll, chips, the beat file, As a sound and Audio file.
3. **Live, Keys and Song**: the keys, takes, ✏️ Layout with keys, pads and grids, ⌨️ Keys on Beats, the Song playlist with tempo marks.
4. **Kids and the welcome**: the four Kids screens, the grown-up sum, Who's playing?, the stage name, tips, dots, the nudge.
5. **The cloud**: the Worker, D1, profiles with PINs, sync and the three-way merge, share codes, the caps, problem reports, usage events, metrics, feedback, the privacy policy, the deploy and its live checks.
6. **Who plays and From a song** last.

Before you start, ask me these, in one batch:

- The domain and the Cloudflare account to deploy to, and who holds the token (it belongs in a GitHub secret, never in the repo).
- Where the licensed recordings may come from for the real-world presets, and which sounds I will record myself (the spoken callouts and the Kids prompts).
- Whether the first milestone ships publicly or stays on a dev server until the second.
- Anything in this prompt you believe contradicts itself: name the two lines.

Then run. Where this prompt is silent, decide by the mission and the five rules in section 1, record the decision in the decisions file in the same commit, and tell me in your report.

## Notes on the prompt (not part of it)

**What it is.** Every line above is a decision an agent would otherwise make differently by default. It is `docs/decisions.md` (about 400 rows), the ADRs, the guide and `AGENTS.md` compressed to about 9,000 words, with everything an agent already does well left out.

**What it will and will not do.** Given to a fresh session, it produces an app with this shape, these words and these rules: a credible 1.0 skeleton with the right red lines baked in. It does not produce this repository: tens of thousands of lines, 2,400 tests, 35 ADRs and a month of corrections. Most of those corrections were found by use (a scroll playing a pad, 🎩 for a hi-hat, a startle sound on a kid's first page), and no amount of prompt writing finds them in advance.

**What makes it rich, in order of weight:**

1. The mission in the author's own words. When the prompt is silent, the agent steers by it. A vague prompt has no mission, so the agent steers by its defaults.
2. Red lines. A constraint prunes more than a feature adds. "No build step" shapes every file; "nobody types a name" shapes the cloud, the backups and the welcome.
3. Defaults named where the agent's default is wrong. Delete on one tap, sound on touchstart, a timer per screen, "Quantize" on a button: each is what an agent builds unasked.
4. The real words: the labels, the emoji, the names of the modes. Without them the agent invents its own, and every later prompt has to translate.
5. Numbers. 320 to 3440, 44 px, 16 rows, 1 · 2 · 4 bars, 4 digits, 25 MB, 3 a day. A number is a decision; an adjective ("big", "fast", "safe") is a deferral.
6. A quality bar a machine can check: a width tool that exits 1, a test that fails without the change, a contrast suite. "Make it polished" checks nothing.
7. Process: how to ask, when to stop, where decisions are recorded. This is what keeps a long session from drifting.
8. A build order and a stop point. "Build the whole thing" gives you a thin everything.

**What a vague prompt actually defers.** "A soundboard for kids" defers every item above to the agent, and then you pay to correct each one, a session at a time. The fix that scales is a page: the mission, the red lines, the real words and numbers you already know, one checkable quality bar, the first milestone, and "ask me the rest before you start". That is sections 1, 2, 8 and 10 of this prompt.

**Where the richness came from.** From the loop this repo already runs: decide, record the rule in one row, build, look at every width, correct, record again. The decisions file is the prompt, grown one row at a time. A fresh app has no such file, so its first prompt can only be a page; by the tenth session, the file is the prompt.

**One check for the next prompt you write.** For each sentence, ask: would an agent that had never seen this do something different without it? If no, cut it. If yes, is it a red line, a word, a number, a check or a question? If it is none of those, it is an adjective, and the agent will fill it with a guess.
